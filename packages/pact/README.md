# @splits/pact

CLI, MCP server, and agent skill for [PACT](https://pact.splits.org): raise
small onchain rounds by selling cap-table units along a USDC bonding curve
on Base. One command table, served three ways.

```sh
npx @splits/pact --help              # CLI
npx @splits/pact skills add          # install the knowledge + command skills into every detected agent harness
npx -y @splits/pact@latest --mcp     # MCP stdio server (or: npx @splits/pact mcp add)
```

The bare `pact` name on npm is unrelated; always spell `@splits/pact`.

## Configuration (env only)

| Variable                    | Default                                        | Meaning                                                                                   |
| --------------------------- | ---------------------------------------------- | ----------------------------------------------------------------------------------------- |
| `PACT_RPC_URL`              | `https://mainnet.base.org`                     | JSON-RPC endpoint                                                                         |
| `PACT_CHAIN_ID`             | `8453`                                         | Expected chain; the CLI refuses to run if the RPC disagrees                               |
| `PACT_FACTORY_ADDRESS`      | pinned Base deployment                         | `OfferingFactory`                                                                         |
| `PACT_FACTORY_DEPLOY_BLOCK` | pin's block (0 when the factory is overridden) | Scan lower bound                                                                          |
| `PACT_PRIVATE_KEY`          | unset                                          | Operator key. Set: writes are signed and sent. Unset: writes return unsigned transactions |
| `PACT_LEDGER_DIR`           | `~/.pact/ledger`                               | Voucher ledger files                                                                      |

The CLI never generates or stores keys.

## Writes

Every write runs the same guardrails, none optional: the target must be a
child of the pinned factory (verified by `OfferingCreated` scan, before any
USDC approve), every transaction is `eth_call`-simulated first, a failing
simulation aborts with the decoded revert, and the exit code is non-zero
whenever nothing was sent. Buys approve exactly `--max-cost`, which defaults to the quote.

- Unsigned (no key, or `--dry-run`): `{ mode: "unsigned", preflight, transactions: [{to, data, value, chainId, description}] }`; pass `--from` so the simulation runs as the eventual signer. Use `--format json` when relaying.
- Key mode: sends in order, waits one confirmation each, returns decoded events.

## Commands

`config` · `offering get|list|quote|cap-table|create` · `buy public|private` ·
`funds withdraw|close|distribute|skim|rescue` · `fail mark|refund|refund-all|sweep` ·
`voucher issue|complete|get|list|cancel` · `admin set-public-units|set-treasury|transfer-ownership|accept-ownership`

MCP tools are the same commands as `<group>_<command>`.

Protocol understanding lives in the repo docs: [architecture](https://pact.splits.org/docs/architecture.md), [contract specification](https://pact.splits.org/docs/contracts.md), [integration guide](https://pact.splits.org/docs/integrate.md).

## Development

The published bundle runs on Node 20+; running from source (`npm run dev -w packages/pact`) needs Node 22.18+ for native type stripping. The chain layer (reads, event decoding, the buy plan) comes from the workspace package `@splits/pact-core` (`packages/core`), which esbuild inlines into the bundle. From the repo root: `npm test` runs the unit tests (`src/**/*.test.ts`),
`npm run test:e2e` packs this package and drives the built binary against
a local anvil. `npm run dev -w packages/pact -- --help` runs from source.

## Publishing

Semver covers the whole command table (names, flags, output envelopes,
derived MCP tool names): major for removals/renames, incompatible schemas,
loosened guardrails, or a moved factory pin; minor for new commands, options,
or output fields; patch for fixes and ABI regeneration. `0.x` until the
factory is stable.

```sh
npm version <bump> -w packages/pact
npm publish -w packages/pact --access public      # prepack: sync + bundle
mcp-publisher login dns                            # splits.org: TXT "v=MCPv1; k=ed25519; p=<pubkey>"
mcp-publisher publish                              # server.json, regenerated by the build
```

Then verify with a registry search and commit the regenerated `server.json`
and `skills/pact/references/onchain-recipes.md` in the same PR.
